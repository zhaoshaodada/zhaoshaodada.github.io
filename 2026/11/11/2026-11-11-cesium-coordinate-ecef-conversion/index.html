Cesium 坐标系实战：WGS84 经纬度与 ECEF 笛卡尔坐标的相互转换

发表于2026-11-11|更新于2026-11-11|前端
|浏览量:

引言

在 Cesium 里做任何三维地理可视化，几乎都绕不开坐标。业务侧给我们的数据通常是「经度、纬度、高程」这种人类可读的地理坐标，而 Cesium 内部渲染、相机运算、实体定位真正使用的是「X、Y、Z 三轴的米制笛卡尔坐标」。

这两套坐标就是 Cesium 最核心的两层表达：一层叫 WGS84 地理坐标系（经纬度 + 相对椭球面高程），另一层叫 ECEF（Earth-Centered Earth-Fixed，地心地固）笛卡尔坐标系，原点固定在地球质心，随地球一起自转，单位是米。

把 GPS 设备坐标、倾斜摄影模型局部坐标落到地球表面，或者算两个大地点之间的距离与朝向，本质都是在这两套坐标系之间来回转换。本文用最小可运行示例，把转换的来龙去脉讲清楚。

原理

WGS84 用经度（longitude）、纬度（latitude）和高程（height）描述一个位置，经纬度以「度」为单位，高程以「米」为单位，但它描述的是相对 WGS84 参考椭球面的高度，而不是平均海平面海拔。

ECEF 则把地球中心当作原点，三个轴固定在地球上（X 轴指向本初子午线与赤道交点，Z 轴指向北极，Y 轴与二者构成右手系），单位固定为米。Cesium 中所有实体的最终位置都必须是 Cartesian3，也就是 ECEF 坐标。

转换的数学基座是 Cesium.Ellipsoid.WGS84（WGS84 椭球）：

  • cartographicToCartesian(cartographic)：经纬度高程 → Cartesian3。
  • cartesianToCartographic(cartesian)：Cartesian3 → 经纬度高程。

Cartographic 是 Cesium 内部表示「弧度 + 高程」的结构，它的 longitude、latitude 都是弧度，不是度。日常开发里我们更常调用两个快捷方法：Cesium.Cartesian3.fromDegrees(lng, lat, height) 内部就是先构造 Cartographic 再做正向转换；而反向转回时，务必要记住返回的是弧度。

如果业务需要的是相对真实地面的海拔而不是椭球面高，还要额外叠加地形高度（通过 sampleTerrainMostDetailed 获取），否则会出现几十米甚至上百米的垂直偏差。

常见坑

  1. 弧度与度数混淆：Cartographic 的 longitude、latitude 是弧度。手动拼接坐标时必须用 Cesium.Math.toRadians / toDegrees 显式转换，否则换算出的 ECEF 坐标会偏差到地球之外。优先用 fromDegrees 系列方法，能省掉这步。

  2. 高程基准不一致：height 默认是相对 WGS84 椭球面的高度，不是海拔。如果和地形（DEM）或业务海拔数据混用而不校正，垂直方向会出现几十到上百米的错位，在做贴地渲染或开挖分析时尤其致命。

  3. 把经纬度当米传：新人常误以为 new Cesium.Cartesian3(x, y, z) 接收的是经纬度。其实它接收的是 ECEF 米坐标，直接把经纬度当米传进去，实体会飞到地球外面几万公里处。

  4. 高频转换的 GC 压力：在 requestAnimationFrame 或大数据循环里反复 new Cartographic / new Cartesian3 会产生大量临时对象。借助 fromDegrees(lon, lat, h, result) 与 cartographicToCartesian(carto, result) 传入复用对象，可以显著减少垃圾回收抖动。

小结

Cesium 的坐标世界只有两层：外层是给人看的 WGS84 经纬度高程，内层是给机器算的 ECEF 笛卡尔坐标。掌握 Ellipsoid.WGS84.cartographicToCartesian 与 cartesianToCartographic 这对互逆操作，再配合 fromDegrees 快捷方法和弧度/度数的显式转换，绝大多数坐标落点、距离测算、模型对齐问题都能迎刃而解。记住高程基准的差异与对象复用两个坑，就能避开线上最隐蔽的那批坐标 bug。
