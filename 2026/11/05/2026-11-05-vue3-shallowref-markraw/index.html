Vue3 shallowRef 与 markRaw：管理大型非响应式对象时的响应式陷阱

发表于2026-11-05|更新于2026-11-05|前端
|浏览量:

引言

在 Vue3 项目里，我们习惯用 ref() 包住一切状态。但当对象是 Three.js 的 Mesh、Cesium 的 Viewer，或一份动辄数千字段的配置文件时，这种“无脑 ref”会触发深度响应式代理：Vue 会递归遍历整个对象，给每个属性套上 Proxy。其结果不仅是性能浪费，更可能因为对象内部存在循环引用、非 configurable 属性或自带 getter，导致代理直接抛错。本文讲清楚 shallowRef 与 markRaw 何时该上场。

原理

ref(value) 在 value 是对象时，底层会调用 reactive() 做深度递归代理；而 shallowRef(value) 只追踪 .value 这一层引用，内部的嵌套属性不会被代理。markRaw(obj) 则给对象打上标记，告诉 Vue 永远不要把它变成响应式——即便它被放进 reactive 或 ref 里也保持原样。三者差异可以用一段最小代码看清：

常见坑

  1. 用 ref 包 Three.js/Cesium 实例时，深度代理可能递归到引擎内部状态，引发“Cannot proxy”类报错或严重的渲染卡顿。
  2. shallowRef 只认 .value 引用。直接修改内部属性（如 heavy.value.meta.label = x）不会自动触发重渲染，必须调用 triggerRef(heavy) 或整体替换 .value。
  3. markRaw 是永久标记，被标记的对象即便后来塞进 reactive 也保持原样，适合存“只读/外部库”对象，但不要把它误用在需要响应的数据上。
  4. 在组合式函数里返回重型对象时，优先 shallowRef(markRaw(x))，并在文档里写明调用方需要 triggerRef 或替换引用来触发更新。

小结

ref 不是万能胶。当对象是外部库实例、大型配置或含循环引用的结构时，让 Vue 深度代理它既无必要也危险。用 shallowRef 控制“何时响应”（替换引用或 triggerRef），用 markRaw 声明“永不响应”，你就能在保持框架能力的同时，把性能与稳定性留在自己手里。
