Vue3 组合式函数实战：封装一个能防竞态、带缓存的 useRequest Hook

发表于2026-11-12|更新于2026-11-12|前端
|浏览量:

引言

在 Vue3 项目里，几乎每个页面都要和异步请求打交道：调接口拿数据、展示 loading、处理错误、组件卸载后还要防止状态回写。如果每次都在组件里手写 loading = true / try / await / catch / finally，不仅重复，还容易踩竞态的坑——先发出的慢请求后返回，把后发出的快请求结果覆盖掉，页面就显示出错乱的数据。

组合式函数（Composable）是 Vue3 推荐的复用逻辑方式。本文我们从零封装一个 useRequest，把 data / error / loading 三件套和「竞态保护 + 可选缓存」一次性解决，并在文末给出可直接在浏览器打开运行的完整示例。

原理

useRequest 的核心是一个返回响应式状态的对象，它把请求动作收敛成唯一的 run() 方法。两个关键技术点：

  1. 竞态保护。用一个自增的 requestId 标记每一次请求。请求完成时，只有当自己的 id 等于「当前最新请求 id」时才允许写入 data 和 loading。这样即使慢请求后到，也因为 id 过期而被丢弃，最终结果永远是最新一次请求。
  2. 可选缓存。当传入 cacheKey 时，把成功结果按 key 存入一个模块级 Map，并设置存活时间 cacheTime。下次命中且未过期时直接复用，跳过网络请求。

它不依赖任何请求库，传入的 fetcher 只是一个返回 Promise 的函数，因此可以搭配 fetch、axios 或任意封装。

常见坑

  • 直接把 run 解构成多个 ref 后，不要在模板里把 run 当普通函数反复 new 调用。每次 run 都自增 requestId，保证了写回收敛，但如果传入的 fetcher 自身会发起多个并发子请求，requestId 只拦最外层，内层需各自处理。
  • 缓存是模块级共享的，多个组件用相同 cacheKey 会互相读取。跨页面共享数据有时是优点，但若数据带用户态，请用「用户 id + key」拼接，避免串号。
  • cacheTime 用绝对时间戳判断，组件卸载不会自动清缓存。长时间驻留的页面若数据易变，要么缩短 cacheTime，要么在关键操作后用 cache.delete(cacheKey) 手动失效。
  • 不要把 immediate: true 和依赖路由参数的请求混用，参数变化不会自动重新请求，应改为 watch 参数后手动 run()。

小结

一个不到 50 行的 useRequest，就帮我们统一了异步请求的 loading、错误、竞态与缓存逻辑。它遵循 Vue3 组合式函数「接收响应式输入、返回响应式状态」的约定，可无缝接入 Composition API。当你把这类通用能力沉淀成 Composable，业务组件就能真正只关心「拿到数据后怎么渲染」，而不是反复搬运样板代码。
