深入理解 JavaScript Proxy 与 Reflect：手写一个最小响应式系统

发表于2026-11-06|更新于2026-11-06|前端
|浏览量:

引言

在 Vue3 的源码里，响应式系统的核心只有两个 API：Proxy 与 Reflect。它们不是什么高深黑魔法，而是 ECMAScript 2015 就正式纳入标准的两个对象。理解它们，不仅能看懂 Vue 的 reactivity 模块，也能在自己的项目里做依赖收集、不可变包装、字段校验等元编程。本文用约 80 行代码，带你从零写一个能跑的最小响应式系统。

原理

Proxy 像一个“代理层”，包裹一个目标对象（target），拦截其读（get）、写（set）等操作。每当你访问 proxy.foo，引擎不会直接读 target.foo，而是调用你定义的 get 陷阱（trap）。Reflect 则提供了一组“默认行为”方法，例如 Reflect.get(target, key, receiver) 等价于默认读取，但它会正确传递 this（receiver），避免继承链上的 getter 拿错 this。

响应式的关键在于：在 get 时记录“谁在读”，在 set 时通知“所有读过它的人重新执行”。我们称前者为“收集依赖”，后者为“触发更新”。

常见坑

  1. 必须写 Reflect.set 而非 target[key] = value。直接赋值会跳过 Proxy，导致嵌套对象再次访问时丢失代理，且 receiver 不对会让继承 getter 出错。
  2. 嵌套对象不会自动变响应式。state.user = { age: 1 } 后，state.user.age 的修改不会被追踪。生产方案是在 get 中递归用 reactive 包装返回值（注意缓存，避免每次都新建 Proxy）。
  3. activeEffect 用全局变量会有并发副作用相互覆盖的问题。Vue 用栈（effectStack）保存，进入 effect 时入栈、退出时出栈，取栈顶为当前活跃副作用。
  4. 默认不处理数组 length 的特殊情况与 Map/Set 的迭代。若需支持集合类型，要额外拦截 size、forEach 等键。

小结

Proxy + Reflect 让 JS 具备了“监听任意读写”的能力，这正是现代前端框架响应式的基石。本文的 80 行实现省略了调度（scheduler）、循环依赖保护、深层响应式等细节，但骨架与 Vue3 完全一致。理解它，你就能在 Three.js/Cesium 这类重状态场景里，自己写一套轻量、可控的订阅逻辑，而不必引入整个框架。
