用 esbuild 写一个极简前端构建器：30 行代码搞定打包与 TypeScript 转译

发表于2026-11-01|更新于2026-11-01|前端
|浏览量:

引言

在日常开发中，我们习惯用 webpack、Vite 这类”全家桶”构建工具，却很少思考它们到底做了什么。本质上，前端构建只解决三件事：把分散的模块聚合成一个文件（打包）、把 TypeScript 与新语法转成浏览器能懂的 JS（转译）、把样式与资源一并处理（资源管线）。esbuild 是一个用 Go 编写的极速构建器，它把这三件事浓缩成了几个清晰的 API。本文不引入任何框架，仅用 esbuild 的 Node API 手写一个最小可用的构建脚本，帮你从零理解构建工具的真实工作流。

原理

esbuild 的核心入口是 build 方法，它接收一个配置对象并返回 Promise。关键字段可以分为三类：

  • 入口与产物：entryPoints 指定入口文件，outfile 或 outdir 指定输出位置；bundle: true 开启依赖收集与合并。
  • 目标与格式：format 决定产物是 esm 还是 iife；target 控制语法降级程度（如 es2020）；platform 区分为 browser 还是 node。
  • 资源与优化：loader 告诉 esbuild 如何处理非 JS 文件（如把 .css 当 css 处理、把图片当 dataurl），minify 与 sourcemap 负责压缩与调试映射。

理解了这些配置，我们就能脱离脚手架，自己掌控构建过程。

常见坑

  1. CSS 必须显式声明 loader。若不写 loader: { '.css': 'css' }，esbuild 遇到样式导入会直接报错；在浏览器端打包时，CSS 默认会被注入到 JS 中随脚本执行。
  2. TypeScript 的类型不会被保留。esbuild 只做”擦除式”转译，不校验类型，因此类型错误不会在构建期暴露，需配合 tsc --noEmit 做独立的类型检查。
  3. bundle: true 才会解析 node_modules 依赖。若只想转译单文件，应关闭 bundle，否则第三方包不会被打进产物。
  4. 平台错配会导致 polyfill 膨胀。给浏览器用却写了 platform: 'node'，会让 esbuild 引入大量 Node 内置模块的垫片，徒增体积。

小结

不到 30 行代码，我们就拥有了一个支持 TypeScript 转译、依赖打包、压缩与监听的构建器。它虽比不上 Vite 的完整生态，却清晰暴露了构建工具的本质：收集入口、解析依赖、转译降级、产出产物。掌握这套思路后，无论是配置 Vite 还是排查 webpack 性能问题，你都能直击要害，而不是被层层封装困住。
