Cesium 加载天地图：底图、注记与地形完整方案

发表于2026-08-01|更新于2026-08-01|教程
|浏览量:

前言

做三维地球项目时，底图选型永远是绕不开的第一步。谷歌影像有访问限制，高德、百度的切片服务坐标系与 Cesium 原生球面墨卡托不完全一致，自己发布切片服务又费时费力。

对于国内项目，天地图（国家地理信息公共服务平台） 是一个非常稳的选择：官方维护、坐标系标准、影像和矢量都齐全、个人开发者免费申请 Token 即可使用。本文就把在 Cesium 中接入天地图的全流程梳理一遍。

一、申请天地图 Token

天地图所有服务都需要带上 tk（Token Key）参数，所以第一步是申请开发者密钥。

  1. 打开 天地图控制台，注册账号并完成实名认证
  2. 进入「应用管理」→「创建新应用」，应用类型选择「浏览器端」
  3. 创建后会得到一串 tk，形如 a1b2c3d4e5f6...，这就是后面所有请求都要带的密钥

注意：浏览器端应用的 Referer 白名单要配置好，否则线上环境会出现 403。本地开发可填 localhost。

二、天地图图层类型一览

天地图服务采用 T=类型 的方式区分图层，Cesium 常用的有：

T 参数 说明 后缀 _c / _w
img 影像底图（卫星影像） _c 经纬度 / _w 球面墨卡托
vec 矢量底图（线划图） 同上
ter 地形晕渲底图 同上
cia 影像注记（中文地名） 同上
cva 矢量注记（中文地名） 同上

关键点：Cesium 默认使用球面墨卡托（WebMercator，EPSG:3857）作为影像图层坐标系，所以优先使用 _w 后缀的服务。_c（EPSG:4326）也能用，但需要额外配置 tilingScheme，没必要自找麻烦。

另外，天地图影像底图本身不带地名标注，需要把 cia（影像注记）叠加在上面才看得清地名，这是新手最容易忽略的一步。

几个参数说明：

  • t{s} 配合 subdomains 做子域名轮询，天地图提供 t0~`t7` 共 8 个子域名，轮询可以绕开浏览器对单域名并发数的限制，加载更快

七、常见问题排查

1. 瓦片加载 403 / 出图全是空白

99% 是 Token 问题。检查：

  • Token 是否复制完整、没有多余空格
  • 控制台里该应用的 Referer 白名单是否包含当前域名（含 localhost）
  • 服务类型是否匹配：浏览器端 Token 不能用于服务端调用

2. 注记和底图对不上、有错位

注记的 tileMatrixSetID 必须和底图一致，都用 w。如果底图用 _w 注记用 _c，坐标系不同会出现明显错位。

3. 缩放到很高级别出灰图

天地图影像最大层级约 18 级，矢量约 17 级。设置 maximumLevel 不要超过上限，否则请求不到瓦片会显示空白。

4. 地形加载后画面卡顿

地形服务会额外请求 DEM 瓦片，网络不好时容易卡。可以：

  • 关闭 requestVertexNormals（不计算法线光照）
  • 限制相机最低高度，避免过度贴近地面
  • 用 viewer.scene.globe.maximumScreenSpaceError 调大采样间隔

总结

Cesium 加载天地图核心就三件事：

  1. 底图：UrlTemplateImageryProvider + T=img_w（影像）或 T=vec_w（矢量）
  2. 注记：叠加 cia_w 或 cva_w，让画面有地名
  3. 地形：CesiumTerrainProvider 接入 swdx 服务

把这三步封装好，一个稳定可用的国内底图方案就成型了。相比自建瓦片服务，天地图省心在：坐标系标准、影像更新及时、地名注记权威。唯一要注意的就是 Token 的 Referer 白名单和层级上限，把这两点盯紧，基本不会踩坑。

如果项目对历史影像或更高精度有需求，可以再叠加本地发布的切片服务作为补充图层，Cesium 的 imageryLayers 支持任意多图层叠加，灵活度足够。
