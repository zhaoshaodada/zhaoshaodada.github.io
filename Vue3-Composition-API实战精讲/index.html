Vue3 Composition API 实战精讲：从 ref 到自定义组合式函数

发表于2026-08-20|更新于2026-08-20|教程
|浏览量:

前言

Vue3 最具革命性的变化就是 Composition API。它解决了 Options API 在复杂组件中”逻辑碎片化”的问题——同一个功能的代码被 data、methods、computed、watch 强行切散到四个角落，维护时要在文件里来回跳转。Composition API 让你能把”一个功能”的所有逻辑聚拢到一起，还能轻松抽出来复用。

本文假设你已经按上一篇文章搭好了 Vite + Vue3 + TS 骨架，重点讲清三个问题：怎么用、什么时候用什么、怎么抽出来复用。

一、<script setup>：一切的开始

Vue3.2 之后推荐用 <script setup> 写法，它是 Composition API 的编译期语法糖，比 setup() 函数更简洁。

特性：

  • 顶层声明的变量、函数自动暴露给模板，无需 return。
  • import 进来的组件直接用，无需注册。
  • 性能更好（编译产物更小）。

三、computed：缓存的派生状态

缓存机制

computed 只有在依赖的响应式数据变化时才重新计算，否则复用上一次结果。这点和 Methods 的”每次调用都执行”截然不同：

computed vs methods

  • 模板里写 {{ calc() }}：每次组件重渲染都会执行。
  • 模板里写 {{ computedVal }}：依赖不变就不执行。

派生状态一律用 computed，能避免大量无谓计算。

六、抽取组合式函数（Composables）

抽取逻辑是 Composition API 最大的收益。把”分页 + 搜索 + 列表”这种业务套路抽成一个 useXxx 函数，多个页面直接复用。

命名约定

  • 文件名 / 函数名都以 use 开头：usePagedList、useTheme、useResizeObserver。
  • 输入参数应是普通值或 ref，输出建议返回 ref / computed，保证调用方使用时还是响应式。
  • 不要在 composable 里直接操作 DOM，让调用方决定怎么用返回值。

七、响应式原理简述

理解原理能少踩很多坑。Vue3 用 ES6 的 Proxy 替代了 Vue2 的 Object.defineProperty。

  • track：在 getter 里把”当前正在执行的 effect”记到这个属性下。
  • trigger：在 setter 里把记录的所有 effect 全部跑一遍。

ref 内部其实就是 reactive({ value: x }) 的封装；computed 是带缓存的”懒执行 effect”。

为什么 Proxy 比 defineProperty 强

  • 能监听新增 / 删除属性（Vue2 要 Vue.set / Vue.delete）。
  • 能监听数组索引和 length（Vue2 要重写数组方法）。
  • 性能更好：一次性代理整个对象，不用遍历每个属性。

八、常见陷阱速查

陷阱 现象 解决
reactive 解构丢响应 模板不更新 toRefs 包装
ref 模板自动解包失效 {{ user.value.name }} 才显示 模板里别写 .value
watch 监听 reactive 整对象 旧值 = 新值 监听 getter 或加 deep
模板里改 props 报错 / 警告 用 computed 派生再改
在异步回调里改 ref 不触发 改了没反应 检查是否解构了 reactive
v-for 里 ref 数组 拿不到 DOM 用函数 ref：:ref="el => setItem(el, item)"

小结

Composition API 的核心心智模型就一句话：用函数组织逻辑，用响应式系统驱动 UI。掌握本文后你能：

  1. 用 <script setup> 写出最简洁的组件。
  2. 在 ref / reactive 之间做正确选择，知道 toRefs 何时出场。
  3. 用 computed 处理派生状态，用 watch / watchEffect 处理副作用。
  4. 把业务逻辑抽成 useXxx，跨页面复用。
  5. 理解 Proxy 响应式原理，遇到坑能自己定位。
