Pinia 状态管理实战指南：从 Vuex 迁移到工程化实践

发表于2026-08-20|更新于2026-08-20|教程
|浏览量:

前言

Pinia 是 Vue3 官方推荐的状态管理库，由 Vue 核心团队成员开发，定位上是 Vuex 5。它解决了 Vuex 的几个老问题：TS 支持差、mutations 写起来啰嗦、模块嵌套太深。在 Vite + Vue3 + TS 这套技术栈里，Pinia 是状态管理的默认选择。

本文延续前两篇的工程化骨架，把状态管理这一层讲透。

一、为什么不用 Vuex

Vuex 在 Vue2 时代是事实标准，但它在 Vue3 + TS 项目里有几个明显的痛点：

维度 Vuex 4 Pinia
TS 支持 类型推断弱，需手写 MutationTree 等 开箱即用，IDE 提示完整
Mutations 必须写 mutation 才能改 state 直接在 action 里改，或直接改
模块嵌套 modules 嵌套，访问要写 namespaced 路径 扁平 store，互相 import 即可
体积 较大 约 1KB（gzip）
Devtools 集成 集成且更直观
Composition API 需 useStore 包装 天然支持

简单说：Pinia = Vuex 减去 mutations 减去 modules 嵌套 + 完整 TS。

三、defineStore 两种写法

Pinia 提供 Options Store 和 Setup Store 两种写法，本质等价，团队统一选一种即可。

Options Store（类 Vuex）

Setup Store（Composition API 风格）

怎么选

  • Options Store：结构清晰，从 Vuex 迁移过来成本低，团队新人上手快。
  • Setup Store：与 Composition API 一致，灵活，能在 store 里用 watch、provide 等。
  • 两者不要混用，按团队约定统一选一种。本文后续示例用 Setup Store。

刷新页面后 state 默认丢失，登录态、主题色这些场景需要持久化。pinia-plugin-persistedstate 是社区方案里最稳的一个。

注意事项

  • 不要持久化大对象：列表数据放 store 又持久化会导致 localStorage 撑爆，仅持久化关键标识，进页面后再请求获取数据。
  • 敏感数据：token 这种放 localStorage 有 XSS 风险，生产环境考虑用 HttpOnly Cookie 或加密存储。
  • SSR 项目：storage 在服务端不存在，需要走 cookie 或自定义 storage 适配器。

十、Devtools 调试

Pinia 与 Vue Devtools 深度集成，能做的几件事：

  1. Time travel：回到任意一次 state 修改前的状态。
  2. 直接编辑 state：在 Devtools 里改值测试 UI。
  3. Action 追踪：看 action 执行的入参、返回、错误。
  4. Getter 实时值：getter 变化时实时显示。

排错流程：打开 Devtools → Pinia 面板 → 选定 store → 看 timeline 里最近几次变更，定位是哪个 action 改坏了 state。

十一、最佳实践速查

场景 建议
只在一个组件用的状态 不要进 store，放组件 ref/reactive 即可
多组件共享的”读多写少” 进 store + computed getter
跨页面共享的会话状态（登录、主题） store + 持久化
列表分页数据 进 store 但不持久化，进页面再请求
表单临时草稿 用 composable 抽取，不要进全局 store
跨 store 调用 action 内部实例化对方 store
大型对象 / 数组改一项 用 $patch 函数式更新，性能更好
store 太大 按业务域拆分，单个 store 别超过 200 行

十二、从 Vuex 迁移清单

Vuex 写法 Pinia 对应
state: () => ({}) state: () => ({}) 或 ref()
getters: { x: (state) => ... } getters: { x: (state) => ... } 或 computed()
mutations: { SET_X(state, v) { state.x = v } } 删除，直接改或写 action
actions: { async fetch() {} } actions: { async fetch() {} } 或函数
dispatch('user/login') useUserStore().login()
commit('user/SET_TOKEN', v) useUserStore().token = v
mapState / mapGetters storeToRefs(useXxxStore())
modules: { user: {...} } 拆成多个 defineStore('user') 文件

小结

Pinia 在 Vite + Vue3 + TS 这套技术栈里几乎是”零学习曲线就能写对”的状态管理库。掌握本文后你能：

  1. 选 Options Store 还是 Setup Store，并按团队约定统一。
  2. 用 storeToRefs 安全解构、用 $patch 批量更新、用 $reset 重置。
  3. 写带缓存的 getters 和返回函数的参数化 getter。
  4. 在 action 内部实例化对方 store，实现跨 store 调用。
  5. 用 pinia-plugin-persistedstate 做选择性持久化，避开大对象和敏感数据的坑。
  6. 按业务域拆分 store 文件，配合 Vue Devtools 高效排错。

下一篇是这套技术栈的最后一环——TypeScript 在 Vue3 里的类型进阶，把 props、emits、provide/inject、泛型组件的类型写法讲透，让类型真正成为开发期的”安全网”。
