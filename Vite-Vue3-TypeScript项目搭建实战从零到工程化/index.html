Vite + Vue3 + TypeScript 项目搭建实战：从零到工程化

发表于2026-08-20|更新于2026-08-20|教程
|浏览量:

前言

Vite、Vue3、TypeScript 已经成为 2026 年前端工程化的”标配三件套”。但很多团队在搭建项目时仍然停留在 npm create vite 后直接写业务的阶段，忽略了目录规范、路径别名、自动导入、代码规范、环境变量这些”看不见但天天用”的工程化配置。

本文将从一行命令开始，搭建一个具备完整工程化能力的 Vite + Vue3 + TypeScript 项目骨架。读完你将获得一份可以直接复用的项目模板，后续的 Composition API、Pinia、类型进阶文章都会基于这套骨架展开。

一、技术选型与前置准备

为什么是 Vite + Vue3 + TypeScript

  • Vite：开发阶段基于原生 ESM，冷启动几乎瞬间完成；生产环境用 Rollup 打包，产物质量有保障。
  • Vue3：Composition API 让逻辑复用更彻底，配合 <script setup> 写法极其简洁，性能也全面优于 Vue2。
  • TypeScript：类型系统把大量低级错误挡在编译期，配合 IDE 的智能提示，重构和协作成本显著降低。

三者结合后，开发体验、可维护性、性能三者兼得，这也是社区主流方案的方向。

环境要求

  • Node.js ≥ 18.12（Vite 5 要求 18+）
  • pnpm（推荐，磁盘占用和安装速度都优于 npm）

十、构建优化

包体积分析

常见优化项

  • 分包：把第三方大依赖单独打成一个 chunk，浏览器缓存命中率更高。
  • 按需引入：Element Plus 通过 unplugin-vue-components 的 Resolver 已经是按需；ECharts 用 echarts/core + use 按需注册。
  • gzip：部署端 nginx 开启 gzip_static on;，构建端用 vite-plugin-compression 生成 .gz 文件。
  • 图片资源：小于 4KB 的会被 Vite 内联成 base64，可以通过 build.assetsInlineLimit 调整阈值。

十一、最终启动流程

一个完整的工程化骨架就跑起来了，目录清晰、规范统一、自动导入到位、构建产物可控。

小结

本文从零搭建了一套 Vite + Vue3 + TypeScript 工程化项目骨架，关键点回顾：

  1. 脚手架：用 create-vue 一次性集成 Vue3 + TS + Router + Pinia + ESLint + Prettier。
  2. 目录规范：按职责分层（api / composables / stores / types / views），后续维护成本低。
  3. 路径别名：vite.config.ts 与 tsconfig 双向配置 @，杜绝相对路径地狱。
  4. 环境变量：.env.development / .env.production 分离，并用 env.d.ts 增强 TS 类型。
  5. 代码规范：EditorConfig + ESLint Flat Config + Prettier，让保存即格式化。
  6. 自动导入：unplugin-auto-import + unplugin-vue-components，告别无意义的 import 重复劳动。
  7. 请求封装：axios 拦截器统一处理鉴权与错误。
  8. 构建优化：分包、可视化、按需引入，控制产物体积。

下一篇我们会在这套骨架之上深入 Vue3 Composition API，把 ref / reactive / computed / watch 的使用边界和最佳实践讲透。
